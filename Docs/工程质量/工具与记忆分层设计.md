# 天命 NovelAgent 工具与记忆分层设计

> **设计目标**: 学习 GenericAgent 和 Hermes Agent，在不同对话阶段暴露不同工具集和记忆深度，降低 token 消耗和响应延迟，同时保持 Agent 自主性。

---

## 一、核心问题

当前架构的致命缺陷：

```csharp
// ❌ 所有阶段都这样
var tools = GetAllTools();              // 20+ 个工具全给模型
var context = BuildFullContext(         // 全量上下文
    chatHistory,                        // 完整对话历史
    workingMemory,                      // 所有工作记忆
    projectMemory,                      // 所有项目记忆
    executionMemory,                    // 所有执行记忆
    ragResults                          // RAG 召回结果
);

var response = await _planner.PlanAsync(context, tools);
```

**问题**:
1. 用户问"章节写完了吗" → 模型看到 20 个创作工具 → 可能误调用 `PlanChapter`
2. 状态查询不需要 RAG，但仍然召回 10 条素材 → 浪费 token
3. 写正文时需要全量记忆，但普通对话时不需要 → 过度加载

---

## 二、对话阶段分类

### 2.1 阶段定义

根据用户意图和任务状态，对话分为 4 个阶段：

| 阶段 | 典型场景 | Token 预算 | 响应目标 |
|------|---------|-----------|---------|
| **Conversation** | 闲聊、状态询问、确认、取消 | 低 (1-2K) | < 2s |
| **Planning** | 规划章节、选择候选、构建上下文 | 中 (3-5K) | < 5s |
| **Creation** | 生成正文、修复草稿 | 高 (10-20K) | 10-30s |
| **Review** | 质量评审、门禁检查、伏笔审计 | 高 (8-15K) | 5-15s |

### 2.2 阶段识别策略

不是预设工作流，而是根据**当前任务状态 + 用户意图**推断：

```csharp
public ConversationPhase InferPhase(
    string userMessage, 
    MissionBlackboard mission, 
    SessionContext session)
{
    // 1. 先看用户意图（轻量快速）
    var intent = ClassifyIntent(userMessage);
    
    if (intent == TurnIntent.StatusQuery)
        return ConversationPhase.Conversation;  // 状态查询永远是对话态
    
    if (intent == TurnIntent.Confirmation && session.PendingAction != null)
        return ConversationPhase.Conversation;  // 确认也是对话态
    
    if (intent == TurnIntent.FreeChat)
        return ConversationPhase.Conversation;  // 闲聊
    
    // 2. 创作意图时，看任务状态
    if (intent == TurnIntent.CreativeBrief || intent == TurnIntent.ContinueMission) {
        var currentTask = mission.GetCurrentTask();
        
        if (currentTask == null || currentTask.Status == "unstarted")
            return ConversationPhase.Planning;   // 需要规划
        
        if (currentTask.Status == "context_ready")
            return ConversationPhase.Creation;   // 准备写正文
        
        if (currentTask.Status == "draft_generated")
            return ConversationPhase.Review;     // 评审阶段
        
        return ConversationPhase.Planning;       // 默认规划
    }
    
    // 3. 修复请求
    if (intent == TurnIntent.RevisionRequest)
        return ConversationPhase.Creation;       // 需要全量记忆修复
    
    return ConversationPhase.Conversation;       // 兜底
}
```

## 三、工具分层暴露

### 3.1 四层工具集

#### **Tier 1: Conversation Tools (对话层)**
```csharp
public static readonly string[] ConversationTools = new[] {
```

### 3.2 工具选择逻辑

```csharp
public string[] GetToolsForPhase(ConversationPhase phase)
{
    return phase switch {
        ConversationPhase.Conversation => ConversationTools,
        ConversationPhase.Planning => PlanningTools,
        ConversationPhase.Creation => CreationTools,
        ConversationPhase.Review => ReviewTools,
        _ => ConversationTools
    };
}
```

**关键**: Agent 仍然自主选择工具，只是**选择范围**受当前阶段限制。

## 四、记忆分层加载

### 4.1 四层记忆策略

| 阶段 | 加载内容 | 为什么 |
|------|---------|--------|
| **Conversation** | Checkpoint + 最近 1 条观察 | 只需要知道当前状态 |
| **Planning** | Checkpoint + ProjectMemory 摘要 + RAG(top=5) | 需要了解项目背景 |
| **Creation** | 全量上下文包 + Story Bible + RAG(top=15) | 需要所有细节写正文 |
| **Review** | Checkpoint + Draft + Gate Reports | 需要评审当前产物 |

### 4.2 记忆加载实现

```csharp
public async Task<AgentContext> BuildContextForPhaseAsync(
    ConversationPhase phase,
    string userMessage,
    SessionContext session,
    MissionBlackboard mission,
    CancellationToken ct)
{
    var context = new AgentContext {
        UserMessage = userMessage,
        Phase = phase,
    };
    
    switch (phase) {
        case ConversationPhase.Conversation:
            // 最小上下文：只要检查点
            context.Checkpoint = await _checkpointService.LoadAsync(session, ct);
            context.RecentObservations = session.Observations.TakeLast(1).ToList();
            break;
        
        case ConversationPhase.Planning:
            // 中等上下文：检查点 + 项目摘要 + 轻量 RAG
            context.Checkpoint = await _checkpointService.LoadAsync(session, ct);
            context.ProjectSummary = await _memoryService.LoadProjectSummaryAsync(mission.ProjectId, ct);
            context.RecentObservations = session.Observations.TakeLast(3).ToList();
            
            // 轻量 RAG：只召回 5 条
            var query = ExtractPlanningQuery(userMessage, context.Checkpoint);
            context.RAGResults = await _ragService.RetrieveAsync(query, top: 5, ct);
            break;
        
        case ConversationPhase.Creation:
            // 全量上下文：完整上下文包
            var task = mission.GetCurrentTask();
            if (task?.ContextPackageId != null) {
                // 已构建的上下文包（包含所有需要的信息）
                context.ContextPackage = await _contextService.LoadPackageAsync(task.ContextPackageId, ct);
            }
            
            context.Checkpoint = await _checkpointService.LoadAsync(session, ct);
            context.StoryBible = await _bibleService.LoadAsync(mission.ProjectId, ct);
            
            // 重量 RAG：召回 15 条
            var creativeQuery = ExtractCreativeQuery(userMessage, context.ContextPackage);
            context.RAGResults = await _ragService.RetrieveAsync(creativeQuery, top: 15, ct);
            break;
        
        case ConversationPhase.Review:
            // 评审上下文：检查点 + 草稿 + 门禁报告
            context.Checkpoint = await _checkpointService.LoadAsync(session, ct);
            
            var reviewTask = mission.GetCurrentTask();
            if (reviewTask?.DraftArtifactId != null) {
                context.DraftArtifact = await _artifactService.LoadAsync(reviewTask.DraftArtifactId, ct);
            }
            if (reviewTask?.GateReportId != null) {
                context.GateReport = await _gateService.LoadReportAsync(reviewTask.GateReportId, ct);
            }
            
            context.RecentObservations = session.Observations.TakeLast(3).ToList();
            break;
    }
    
    return context;
}
```

## 五、实际案例对比

### 案例 1: 用户问 "章节写完了吗"

#### ❌ 当前做法
```
Token 消耗: ~8000
- 完整对话历史 (2000)
- 所有工作记忆 (1000)
- 20 个工具 schema (2000)
- RAG 召回 10 条 (2000)
- 项目记忆 (1000)

响应时间: ~5s
风险: 可能误调用 PlanChapter
```

#### ✅ 分层做法
```
阶段识别: Conversation (状态查询)
工具暴露: 4 个对话工具
记忆加载: Checkpoint only

Token 消耗: ~500
- Checkpoint (200)
- 4 个工具 schema (200)
- 最近 1 条观察 (100)

响应时间: ~1s
风险: 无，只能调用查询工具
```

### 案例 2: 用户说 "继续写第 3 章"

#### ❌ 当前做法
```
Token 消耗: ~12000
响应时间: ~8s
问题: 
- 规划阶段和创作阶段混在一起
- 不知道是要规划还是生成正文
```

#### ✅ 分层做法
```
步骤 1: 阶段识别
- 意图: ContinueMission
- 任务状态: context_ready
- 推断阶段: Creation

步骤 2: 加载创作上下文
- ContextPackage (已构建，包含完整信息)
- StoryBible
- RAG top=15

Token 消耗: ~15000
响应时间: ~10s

步骤 3: 只暴露创作工具
- GenerateChapterWithChanges
- RepairChapterDraft
- ValidateChapterDraft

结果: Agent 自主选择 GenerateChapterWithChanges，精准执行
```

## 八、与工作流的本质区别

### ❌ 工作流
```
if (state == "planned") {
    只能调用 BuildContext;
} else if (state == "context_ready") {
    只能调用 GenerateChapter;
}
```
→ 硬编码流程，Agent 没有选择

### ✓ 阶段化上下文
```
if (phase == Planning) {
    tools = [Search, Plan, Select, Build, AskUser];
    context = Checkpoint + ProjectSummary + RAG(5);
}

Agent 从 5 个工具中自主选择:
- 可能先 Search
- 可能先 AskUser
- 可能直接 Plan
```
→ Agent 仍然自主，只是**上下文更精准**

### 9.2 SOP 外化
```markdown

## 章节规划流程

当用户要求规划新章节时:
1. 先 SearchCreativeKnowledge 了解类型约定
2. 调用 PlanChapter 生成 3 个候选
3. 让用户通过 AskUser 选择
4. 调用 SelectChapterCandidate 确认选择
5. 更新 Checkpoint
```

### 9.3 子 Agent 评审
```csharp

var reviews = await Task.WhenAll(
    DelegateReviewAsync("character_motivation", draftId),
    DelegateReviewAsync("foreshadowing_check", draftId),
    DelegateReviewAsync("prose_style", draftId)

// 主 Agent 汇总裁决
var verdict = await _reflectionEngine.JudgeAsync(reviews);
```

**总结**: 这不是限制 Agent，而是**让 Agent 在合适的上下文中做合适的决策**。就像人类作家：闲聊时不会翻出所有素材，真正写作时才全神贯注调动所有记忆。
