用户设置页面重构设计

基于多用户架构的设置页面组织方案

⚠️ 当前问题

  • 5个标签页混杂了用户级设置（LLM配置、界面偏好）和创作默认值（章节字数）
  • 没有账号管理功能（用户名、密码、邮箱等）
  • 没有角色权限展示
  • 缺少用户配额/使用统计（AI调用次数、存储空间等）
A

方案A：扁平化标签页（7个）

1. 账号信息 - 用户名、邮箱、密码、角色标识
2. 大模型配置 - LLM API 设置（保留）
3. Embedding 模型 - RAG 配置（保留）
4. Agent 设置 - 风险等级、自动步数（保留）
5. 创作默认值 - 章节字数、类型（保留）
6. 界面偏好 - 主题、语言（保留）
7. 使用统计 - API调用次数、存储空间、账号状态

优点：结构清晰，每个标签页职责明确
缺点：标签页数量多，可能显得拥挤

B

方案B：分组折叠（推荐）

🧑 账号与安全 - 个人信息、密码、角色、使用统计
🤖 AI 配置 - LLM设置、Embedding设置、Agent行为（合并3个标签）
✍️ 创作偏好 - 默认章节字数、类型、文风偏好
🎨 界面与通知 - 主题、语言、通知设置

每个标签页内部使用可折叠的分组面板（类似 Notion/Linear），默认展开常用项。

优点：减少标签数，分组逻辑清晰
缺点：需要实现折叠组件

C

方案C：双栏导航

账号管理
个人信息
安全设置
使用统计
系统配置
AI 配置
创作偏好
界面设置
→ 右侧显示选中项的配置表单

优点：类似 VS Code 设置页，支持更深层级
缺点：需要重构整个布局结构

推荐方案B：标签页数量适中（4个），通过折叠面板解决内容复杂度，改动成本可控。
