基于现有架构的数据库迁移方案

混合方案：SQLite + 保留文件向量索引（渐进式迁移）

🎯 核心发现
✓ 项目未使用任何数据库，纯文件系统存储（JSON + Markdown）
✓ 已实现自研向量索引（int8 量化，三层检索）
✓ 本地 Embedding（bge-small-zh-v1.5，512维）
✓ 最大痛点：数据完整性缺失（删除章节后伏笔引用仍存在）
✓ 性能瓶颈：Story Bible 单文件 52K+ tokens
A

渐进式混合方案（推荐）

Phase 1: 元数据迁移 SQLite（优先级：高）
迁移内容：
• projects.json → projects 表
• story_bible.json 核心字段 → chapters, foreshadows, characters 表
• 添加外键约束（删除章节自动清理伏笔引用）
• 添加事务保护（解决并发写入冲突）
Phase 2: 保留现有优势
不动部分：
• ✅ 章节内容仍为 Markdown 文件（版本控制友好）
• ✅ 向量索引保持文件存储（1000章以内够用）
• ✅ 本地 Embedding 服务不变
• ✅ 复杂 JSON 结构保留文件（减少迁移成本）
收益：
✓ 解决引用完整性问题（最高优先级）
✓ 支持结构化查询（"找出所有未解决的伏笔"）
✓ 并发安全（事务保护）
✓ 零配置部署（SQLite 单文件）

开发周期：2-3周 | 风险：低

B

PostgreSQL + pgvector（一步到位）

全面升级
• 所有结构化数据 → PostgreSQL
• 向量数据 → pgvector 扩展（HNSW 索引）
• 高并发支持（MVCC）
• 生产级性能
代价：
✗ 需要部署 PostgreSQL 服务
✗ 运维复杂度高
✗ 迁移成本大（4-6周）
✗ 当前规模不需要这么重

适用场景：章节数 >2000 或 高并发需求

C

SQLite + 外部向量数据库

混合架构
• 结构化数据 → SQLite
• 向量数据 → Qdrant/Milvus（Docker 部署）
• 专业向量检索（HNSW 索引）
评估：
⚠️ 当前文件向量索引性能尚可（<100ms）
⚠️ 引入外部服务增加复杂度
⚠️ 建议等章节数 >1000 再考虑

时机：向量检索延迟 >200ms 时迁移

📋 方案A详细设计（推荐）

-- 用户表（新增）
CREATE TABLE
users (
id TEXT PRIMARY KEY,
username TEXT UNIQUE NOT NULL,
email TEXT UNIQUE NOT NULL,
password_hash TEXT NOT NULL,
role TEXT NOT NULL CHECK(role IN ('admin', 'author')),
storage_quota_mb INTEGER DEFAULT 5120,
api_call_quota INTEGER DEFAULT 10000,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
is_active BOOLEAN DEFAULT 1
);
-- 用户设置表（从 user_settings.json 迁移）
CREATE TABLE
user_settings (
user_id TEXT PRIMARY KEY,
llm_provider TEXT, llm_api_key_encrypted TEXT,
llm_model TEXT, llm_temperature REAL DEFAULT 0.7,
agent_default_risk TEXT DEFAULT 'Medium',
theme TEXT DEFAULT 'dark',
FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);
-- 小说项目表（从 projects.json 迁移）
CREATE TABLE
novel_projects (
id TEXT PRIMARY KEY,
user_id TEXT NOT NULL,
title TEXT NOT NULL,
genre TEXT, sub_genre TEXT,
core_hook TEXT,
status TEXT DEFAULT 'draft',
word_count INTEGER DEFAULT 0,
storage_project_name TEXT UNIQUE,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);
-- 章节元数据表（从 Story Bible 提取）
CREATE TABLE
chapters (
id TEXT PRIMARY KEY,
project_id TEXT NOT NULL,
volume_id TEXT,
title TEXT NOT NULL,
chapter_number INTEGER NOT NULL,
word_count INTEGER DEFAULT 0,
status TEXT DEFAULT 'draft',
content_path TEXT NOT NULL, -- 指向 Markdown 文件
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
FOREIGN KEY(project_id) REFERENCES novel_projects(id) ON DELETE CASCADE
);
-- 伏笔账本表（关键！解决引用完整性问题）
CREATE TABLE
foreshadows (
id TEXT PRIMARY KEY,
project_id TEXT NOT NULL,
name TEXT NOT NULL,
type TEXT,
status TEXT DEFAULT 'planned',
setup_chapter_id TEXT, -- 外键保护
payoff_chapter_id TEXT,
importance INTEGER,
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
FOREIGN KEY(project_id) REFERENCES novel_projects(id) ON DELETE CASCADE,
FOREIGN KEY(setup_chapter_id) REFERENCES chapters(id) ON DELETE SET NULL,
FOREIGN KEY(payoff_chapter_id) REFERENCES chapters(id) ON DELETE SET NULL
);
-- 角色表（从 Story Bible 提取）
CREATE TABLE
characters (
id TEXT PRIMARY KEY,
project_id TEXT NOT NULL,
name TEXT NOT NULL,
identity TEXT, role_type TEXT,
first_appearance_chapter TEXT,
detail_json_path TEXT, -- 复杂数据仍存文件
FOREIGN KEY(project_id) REFERENCES novel_projects(id) ON DELETE CASCADE,
FOREIGN KEY(first_appearance_chapter) REFERENCES chapters(id) ON DELETE SET NULL
);
-- Agent 记忆表（从 JSON 迁移）
CREATE TABLE
agent_memories (
id TEXT PRIMARY KEY,
user_id TEXT NOT NULL,
project_id TEXT, -- NULL = author_memory（全局）
memory_type TEXT NOT NULL CHECK(memory_type IN ('author', 'project', 'execution')),
content TEXT NOT NULL, -- JSON 格式
updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);
-- 索引优化
CREATE INDEX
idx_chapters_project ON chapters(project_id);
CREATE INDEX
idx_foreshadows_status ON foreshadows(status);
CREATE INDEX
idx_memories_user_project ON agent_memories(user_id, project_id);
