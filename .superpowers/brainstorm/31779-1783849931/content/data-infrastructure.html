数据库、Redis 与 Qdrant 的职责边界

一个权威状态源，两个可重建加速层

数据库：权威状态
作品与候选正史Story Bible、章节版本、CanonBranch、候选事实、依赖关系
创作任务CreativeGoal、任务图、内核任务、状态转换、协作模式与授权
知识资产原始文档元数据、摘要、分类、StyleProfile、项目使用记录与引用
审计与恢复领域事件、审稿报告、RevisionPlan、幂等记录、Outbox
Redis：协调与热点缓存
分布式 Lease任务 claim、章节/批次互斥、自动续租；数据库仍裁决任务状态
实时事件SSE fan-out、短期 replay、进度广播；权威事件保存在数据库
版本化缓存项目快照、Context Contract、知识包、会话摘要和热点查询
失效规则键含 user/project/branch/version；事件提交后失效，不依赖纯 TTL 正确性
Qdrant：派生召回索引
用户全局知识摘要、知识条目、抽象 StyleProfile、来源片段向量
项目作品索引正史片段、候选分支片段、章节摘要、事实和叙事承诺
强制元数据过滤user、project、branch、sourceType、version、status、chapter
只返回候选 ID数据库批量回读真实内容、权限和版本后才能进入 Knowledge Pack
数据库事务提交 → Outbox / Domain Event → Redis 失效与广播 + Qdrant 增量索引
Redis 清空任务和作品不丢失；从数据库恢复队列与缓存，只暂时降低实时性和性能
Qdrant 清空作品仍正确；从数据库文档、事实、知识和版本重新生成全部向量
数据库不可替代任何缓存命中和向量召回都不能绕过数据库的租户、版本、分支和权限校验
