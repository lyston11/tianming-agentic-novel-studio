Qdrant 驱动的长文本召回

先定位文档区域，再回读完整上下文；不把孤立向量片段直接塞给写作模型

入库：多尺度索引
文档摘要向量整本资料或长文档主题、用途、时间与来源
章节 / Section 向量按标题和语义边界形成父节点摘要
语义 Chunk 向量按段落、场景、论点切分；保留 parentId、位置和邻接关系
事实 / 实体 / StyleProfile 向量结构化知识的独立检索入口
→
查询：多路召回与扩展
查询规划将章节任务拆成角色、设定、事件、主题、文风和知识问题
并行粗召回Qdrant dense vector + sparse/关键词 + 元数据过滤，各路取 30–80 个候选
融合与重排RRF 融合；cross-encoder / reranker 结合章节任务重排至 8–15 个锚点
父子与邻窗扩展命中 chunk 后，从 PostgreSQL 取父 section、前后段、关联实体和依赖事实
去重与矛盾检测同源合并、版本淘汰、正史冲突标记、候选分支隔离
→
输出：可验证上下文
Evidence Bundle完整片段、文档标题、位置、版本、来源和召回理由
Context Compression围绕当前章节问题压缩，不改写专名、数字、规则和引用
预算分区硬事实保底；连续性、任务合同、知识素材和风格分别限额
Knowledge Pack写作模型只看到经过验证、带引用且不冲突的最终包
全局知识只按 userId 过滤；任何项目都可召回，实际采用后记录项目使用
正式作品按 userId + projectId + canonVersion 过滤
候选批次按 branchId 隔离，只允许当前批次及其基线正史
超长小说邻近章直接读取，远距离剧情通过摘要、实体、事件和片段四路召回
