PostgreSQL 目标数据架构

生产唯一权威库；为候选分支、任务图和多内核并发提供原生事务语义

领域模型
作品聚合projects、canon_snapshots、story_entities、chapter_versions、continuity_facts
候选分支canon_branches、candidate_chapters、candidate_facts、fact_dependencies
创作执行creative_goals、task_graphs、kernel_tasks、domain_events、revision_plans
知识资产knowledge_documents、knowledge_entries、style_profiles、knowledge_usages、citations
并发与一致性
原子任务领取FOR UPDATE SKIP LOCKED，多 worker 无重复执行
乐观并发聚合 version / xmin，返工和分支合并检测陈旧写入
部分唯一索引每会话 active goal、每章 active task、幂等键和未完成批次约束
JSONB + 关系字段可变报告与模型产物用 JSONB；身份、状态、依赖、权限必须关系化
事务 Outbox领域状态与待发布事件同事务提交，Redis/Qdrant 异步消费
从 SQLite 迁移
独立 PostgreSQL baseline不重放含 PRAGMA 的旧 SQLite migration
离线导入器SQLite 只读导出 → 类型转换 → PostgreSQL staging → 校验 → 正式表
双重核验行数、外键、哈希、章节版本、用户归属、知识向量引用
切换与回滚短暂停写、最终增量、切换连接；原 SQLite 保持只读备份
生产环境只支持 PostgreSQL。任务调度、分支合并和 Outbox 按 PostgreSQL 语义实现并测试。
开发环境优先使用容器 PostgreSQL；SQLite 仅用于纯领域单元测试或迁移源测试，不能证明生产并发正确性。
