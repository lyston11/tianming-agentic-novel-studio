# 天命 Agentic Novel Studio 开源说明

## 项目定位

天命 Agentic Novel Studio 是一个面向长篇小说创作的 AI Agent 工作台。项目重点不是一次性生成文本，而是把创作目标、章节计划、人物与世界设定、知识资料、连续性事实、审稿结果和返工任务组织成可追踪的生产流程。

当前仓库实现的是 Web 架构：

- React + TypeScript 前端；
- ASP.NET Core 8 后端；
- PostgreSQL 16 权威业务数据库；
- Redis 运行协调与实时事件；
- Qdrant 可重建向量索引；
- 本地 BGE 中文嵌入模型。

旧版 WPF 桌面应用说明不代表本仓库当前实现。

## 核心能力

### Agent 创作工作流

- 将用户创作意图编译为 Creative Goal 和可执行任务图；
- 按章节组织设定、规划、知识检索、正文生成和质量审查；
- 记录任务状态、模型执行、成本预算、Artifact 和 Domain Event；
- 支持暂停、恢复、失败重试和人工返工；
- 通过实时事件向前端展示 Goal 和任务进度。

### 长篇一致性维护

- Story Bible、角色状态、世界规则、伏笔和连续性摘要；
- Canon 分支、变更提取和合并冲突检查；
- 章节事实沉淀和跨章节状态追踪；
- 连续性审查与文学质量审查双通道；
- 基于结构化证据执行定向返工，而不是整章盲目重写。

### 知识库与 RAG

- 文档上传、结构化处理、Section 和 Chunk 管理；
- PostgreSQL 全文检索与 Qdrant 向量检索融合；
- 查询规划、实体依赖检索和 Reciprocal Rank Fusion；
- 所有向量命中均回 PostgreSQL 校验用户归属、版本和正文；
- Qdrant 数据丢失后可由 PostgreSQL 权威内容重建。

### 多用户与可靠性

- JWT 身份认证和项目归属校验；
- PostgreSQL Row-Level Security 用户隔离；
- 后台任务 claim、lease、幂等结算和 Outbox；
- Redis SSE live/replay 与事件 fan-out；
- PostgreSQL、Redis、Qdrant 和 embedding 统一健康检查。

## 数据权威边界

系统遵循单一业务真源原则：

- **PostgreSQL**：保存用户、项目、章节、知识、记忆、Goal、任务、模型执行、审稿和审计数据，是唯一业务真源；
- **Redis**：保存 lease、缓存、SSE replay 和事件广播等短期运行状态，不保存不可替代的作品事实；
- **Qdrant**：保存向量、内容哈希和定位信息，只作为可重建检索索引；
- **本地文件**：仅用于配置、模型资源、构建产物或明确的导入导出，不作为生产业务状态的隐式权威来源。

详细设计见 [Docs/ARCHITECTURE.md](Docs/ARCHITECTURE.md)。

## 快速启动

### 环境要求

- Docker 24 或更高版本；
- Docker Compose v2；
- 如需本地开发：.NET SDK 8、Node.js 18 或更高版本。

### 使用 Docker Compose

复制环境变量模板：

```bash
cp .env.example .env
```

为下列变量设置独立的高强度随机值：

```dotenv
NOVELAGENT_ADMIN_PASSWORD=
NOVELAGENT_APP_PASSWORD=
NOVELAGENT_WORKER_PASSWORD=
NOVELAGENT_JWT_SECRET=
```

启动服务：

```bash
docker compose up -d --build
```

默认 API 与发布版前端地址为：

```text
http://localhost:5002
```

Qdrant 本地管理端口为 `6333`，gRPC 端口为 `6334`。PostgreSQL、Redis 和 Qdrant 不应直接暴露到公网。

完整初始化、迁移、备份、恢复和故障排查流程见 [Docs/DEPLOYMENT.md](Docs/DEPLOYMENT.md)。

## 安全说明

- 不要提交 `.env` 或任何真实凭据；
- `.env.example` 只能保留占位符；
- 生产环境必须使用独立的管理员、应用和后台 worker 数据库账号；
- JWT Secret 应使用至少 32 字节的高熵随机值；
- 发布前应检查 Git 历史中是否曾包含密钥、数据库、用户作品或构建产物；
- 对外服务应配置 HTTPS、反向代理、访问控制、备份和监控。

发现安全问题时，请不要在公开 Issue 中粘贴凭据、用户数据或可直接利用的攻击细节。
