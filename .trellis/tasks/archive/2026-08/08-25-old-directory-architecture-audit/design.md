# 技术设计：old 目录审计报告

## 分析边界

只读审计 `old/`，优先分析解决方案项目、架构/实施文档、领域与应用代码、Web 入口、Pi Runtime、Worker/模块服务、回归测试和迁移脚本。缓存、SDK、node_modules、bin/obj、备份与临时探针只做分类记录。

## 证据方法

1. 使用目录与文件清单建立地图。
2. 读取解决方案、项目引用、入口配置和关键文档。
3. 通过类型/服务/数据库上下文/Worker/测试名称追踪主要链路。
4. 对照 Git 提交历史和根目录 core-first 架构，区分已落地、验证过、规划中和遗留。
5. 输出路径锚点与置信度，避免把设计文档当成运行时事实。

## 报告结构

- 快速结论
- 目录地图与内容分类
- 历史时间线
- 产品目标与设计原则
- 代码架构和依赖边界
- Agent-to-Canon 业务链路
- 数据、异步和部署模型
- 测试/任务/文档体系
- 与当前新架构的关系
- 应保留、迁移、替代、废弃与风险

## 重要取舍

报告追求可维护的导航和决策支持，不追求逐文件目录转储。历史源码只在能解释边界、行为、风险或迁移依据时展开；结论必须标明证据类型。
