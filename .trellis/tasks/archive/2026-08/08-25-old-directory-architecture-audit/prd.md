# 拆解 old 目录历史与架构

## Goal

为后续开发建立一份可检索、以仓库证据为依据的 `old/` 历史与架构地图，解释其代码、设计思想、产品目标、重要任务、迁移状态及当前新架构的继承关系。

## Requirements

- 覆盖 `old/` 的主要目录、项目、文档、测试、脚本、运行时与资源，并区分产品代码、工程基础设施、历史材料、生成物和临时内容。
- 基于 Git 历史、项目文件、架构文档、任务文档和关键源码，说明演进阶段与重要转折。
- 梳理从用户对话到 Agent、Goal、Production、Task、Candidate/Acceptance、Canon 的主要设计链路；若某条链路仅存在于设计或测试中，必须明确标注。
- 说明核心边界、数据存储、异步 Worker、Outbox、权限/租户隔离、Web/SSE、Node Pi Runtime 等关键思想及其取舍。
- 盘点重要任务与完成状态，指出现行新架构应继承、迁移、替代或废弃的内容。
- 输出中文 Markdown 报告，所有关键结论尽量附仓库内路径锚点；不修改 `old/` 产品代码。

## Constraints

- `old/` 是历史代码与设计材料，不能把文档中的目标架构误报为已实现行为。
- 仓库当前 core-first 重构后的根目录架构及现有项目记忆是解释迁移关系的参照，但本任务不做代码迁移。
- 需要识别临时文件、私密配置、构建产物和备份，避免把它们作为设计依据。

## Acceptance Criteria

- [ ] 报告包含目录地图、历史时间线、架构分层、关键数据/调用链、重要任务、测试与部署体系、迁移判断和风险清单。
- [ ] 报告明确区分“已实现 / 测试验证 / 设计规划 / 历史遗留”。
- [ ] 报告引用的主要路径真实存在，且结论可由仓库内容复核。
- [ ] 报告保存于本 Trellis 任务目录，并通过路径存在性与基本覆盖检查。

## Out of Scope

- 不修复、迁移、删除或重构 `old/` 中代码。
- 不执行完整解决方案构建、数据库迁移或端到端环境部署。
- 不逐一解释全部生成文件、依赖包和二进制内容；只记录其类别、用途和是否应作为架构依据。
